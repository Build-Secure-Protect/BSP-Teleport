Portal Core screen: a bigger layout

Three options for the core screen at a new size, 440 by 270 GUI units instead of 300 by 214, with the same small text. It fills more of the window and the text comes out smaller next to it. Each option also fixes the three layout points from the report: somewhere obvious to name the portal, picker names that are not cut off, and nothing running past the edge. The text fixes (plain button names, no raw keys, the new help line) are already built and are the same in all three.

A. Name row on top, detail line under the picker default

The DESTINATION tab gains a Name row with a Rename key. Picker rows show the name and the server on one line; the selected one is spelled out in full underneath, with where it is.

C fits fewer picker rows and pushes the two switches into the footer line (they move to the Open/close tab).

Applies to all three

  • The panel is 440 by 270 GUI units and takes up to about 90 % of the window; the client setting ui.screenScale (config/bsp_teleport-client.toml, default 1.5) still caps the size, so a smaller number there makes every BSP-Teleport screen smaller.
  • Every text that can be long (portal, warp and server names, labels, help lines) is cut with "..." to the space it has, so nothing runs past a key or the panel's edge; the other tabs get the same check.
  • New Portal Cores are named "Portal 1", "Portal 2" and so on, the next free number on the network, and Rename refuses a name another portal already uses, so /bsptp portal <name> and the pickers always find one portal.
  • Portal pickers show the server in violet when it is another one, and the position, so two portals with similar names can be told apart.
